# ADR-0002：双路相机与画面合成输出模式

- 状态：accepted
- 日期：2026-11-06

## 背景

产品行为要求双路 MIPI 相机输入，默认"双画面合成 + 单路编码推流"，同时允许独立流与
单路降级。需要确定输出模式、合成布局、同步策略与编码/推理的解耦方式。

## 决策

1. **三种模式，composite 为默认**：
   - `composite`：两路经时间戳对齐后 RGA 合成（默认 side-by-side，可配置布局），
     单路 MPP 编码，默认单路 RTSP 发布。
   - `independent`：两路独立编码、独立 stream path（可配置）。
   - `single`：单路降级运行（任一路掉线自动切换，另一路继续推流）。
2. **合成规则**：合成前统一像素格式/尺寸/stride/色彩空间（禁止忽略 stride）；
   输出尺寸与布局由配置决定（composition.*）。
3. **同步策略**：最近邻 + 最大容差（sync_tolerance_ms）；超阈值标记不同步并丢弃旧帧，
   记录 align_error/desync_count 指标。内部时间戳一律 CLOCK_MONOTONIC，墙上时间另行保存。
4. **推流与推理解耦**：推流 25/30fps 独立节拍；推理 5~10fps 独立采样（配置化、实测决定），
   推理结果只关联 frame_id，不阻塞推流链路。
5. 每路相机独立配置分辨率/帧率/像素格式/曝光/增益；MIPI Bayer 输入时 ISP 由 BSP 驱动完成，
   用户态不得把 Bayer 当 RGB/NV12 用。

## 后果

- 正向：单路故障可降级；推流延迟不受推理影响；布局/分辨率全部可配置。
- 代价：需要帧同步器、对齐指标与合成池管理（Phase 2 交付）。
- 审计支撑：B 的 combineImage 是 2×3 六宫格且与推流配置 1280×720 不一致、无同步策略，
  本决策以双路 side-by-side + 显式同步替代；参考仓库只有单相机假设，需引入 Channel 抽象。
