# ADR-0003：缓冲区所有权

- 状态：accepted
- 日期：2026-11-06

## 背景

零拷贝链路（V4L2 DMABUF → MPP 解码 → RGA 合成 → MPP 编码 → 发布）需要明确每块缓冲的
所有权与归还时机。审计发现两种极端：参考仓库有严谨的 holder/延迟归还协议；
B 项目是拷贝型链路且存在"多模型共享同一 Mat 并发画框"等生命周期隐患。

## 决策

1. **所有权协议采用参考仓库模式并强化**：
   - 相机缓冲：dma-heap 池 + `V4L2_MEMORY_DMABUF` 注入；仅当解码（或跳帧路径）完成后
     经 recycle 队列回 capture 线程 QBUF；丢帧也必须先归还。
   - 解码输出：`DecodedTaskHolder` 持有 MppFrame/MppBuffer 引用直到全部下游（RGA/合成/
     可选采样）完成；经 PendingRecycleQueue 延迟一轮归还，避免复用冲突。
   - RGA 输出/合成池：惰性建池 + in_use 位图 + 幂等归还。
   - 编码输入：`encode_put_frame` 阻塞返回即视为消费完成，立即归还上游池；
     fd 在编码器侧会话期常驻。
2. **引用计数 + 显式归还**：跨线程共享帧（如推流与推理同源）用引用计数；
   归还接口一律幂等；错误路径与关停时 drain 全部在飞缓冲。
3. **禁止**：在 RGA/推理未完成时 QBUF/回收；以"fd 进了队列"推断缓冲可释放；
   多消费者无同步写同一像素缓冲（审计教训：B 的 4 模型共享 ori_img 画框）。
4. **推理缓冲**：Phase 3 以 rknn_inputs_set 拷贝路径起步（安全），目标板评估
   rknn_set_io_mem 零拷贝并遵循其保活约定；RKNN 输入/输出缓冲生命周期由 RknnRuntime
   封装持有。
5. fence/cache 规则以实际 SDK 文档与目标板实测为准，**不臆造**；文档标注 UNVERIFIED。

## 后果

- 正向：确定性回收、无 UAF/泄漏、可压力测试；host 可用"所有权状态机"纯逻辑测试。
- 代价：每条边都需要 holder 与归还协议，实现量增加。
- 审计支撑：修复 A/B 的 mpp_ctx 遮蔽泄漏、运行中 delete、回调内每帧 malloc、
  多模型并发画框等问题；将参考仓库无界队列改为有界 + 丢帧策略。
